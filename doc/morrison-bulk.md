The bulk Morrison variant uses the same neuron equations, checkpoint state and learning order described in [Morrison](morrison.md). Build `sys/morrison_bulk.bin` for ABI2 with the original polling completion, or `sys/morrison_bulk_tree.bin` for ABI2 with forward completion through a reduction tree. `morrison_g1.bin` and `morrison_g4.bin` remain ABI1 baselines.

Plastic rows are consecutive within each home PU's MC section. Full chunks contain 128 FP32 weights followed by 128 packed destinations. Each row ends with an invalid-destination sentinel; the two tail halves are separately rounded to 32 bytes. A row with n real synapses occupies `64 * ceil((n + 1) / 8)` bytes, including its sentinel. Delegation splits at chunk boundaries relative to that row, so every worker receives complete weight/destination pairs.

Each home caches its E-row boundaries in scratchpad: at most 177 words (708 bytes) on the full target. The reserved region is `0x2ea0..0x3220` (896 bytes), allowing the smaller functional configurations' worst local count too. Coroutine controls and two buffer descriptors occupy `0x2040..0x2100`. The tree uses another 44 bytes at `0x2100..0x212c` for home completion and receiver count state. The two balanced-dispatch words use existing control space at `0x20b8` and `0x20bc`. These changes add no neuron fields or cached row pointers. The two streaming banks remain at `0x3700..0x3b00` and `0x3b00..0x3f00`; neuron records, reverse MSHRs, refill buffers and stack guards retain their addresses.

Static edges are merged by whole destination MC. Static and reverse directories have a fixed, line-rounded stride and are indexed directly by the home's local neuron slot. Runtime row-descriptor fetches are absent from this variant. Reverse entries point to the new physical locations of individual plastic weights, including parallel edges.

An incoming job carries begin/end MC-local byte offsets, auxiliary data and owner-MC/kind context in four words. Static auxiliary data names the first destination MC; the plastic auxiliary word is unused. In the tree payload the context also includes the home PU for returning a completed-range count: owner MC in bits 0–15, kind in bit 16, and home PU in bits 17–26. The executor needs neither the source neuron ID nor the group size. The manifest's `group_size=1` describes whole-row storage, not the number of execution workers.

The CLI accepts balanced dispatch widths 1, 2, 4, 8, 16 and 32, bounded by the number of PUs per MC; select this policy with `--dispatch-policy balanced`. On the 512-PU/16-MC target, G32 uses all 32 workers in the source's MC domain; G16 uses an aligned subgroup of 16 within it. If a plastic row has C physical 1 KiB chunks, each of G workers gets `floor(C/G)` chunks and the first `C mod G` get one more. Worker ranks rotate from the source home. The last range stops at the actual row end, and zero-byte ranges are not sent. A row with no real edges still has a 64-byte sentinel block. On the full target, static directory work uses `min(G, 4)` workers: G of at least 4 gives one 32-byte line per worker, while G1/G2 gives four/two lines per worker. The `legacy` policy preserves ceil-based partitioning with widths 1, 2 or 4. The optional parameter word at `MR_PARAMETERS+32` selects legacy=0 or balanced=1; the word at `+36` selects polling=0 or tree=1. Both policies use the same whole-row matrix layout.

SMT0 preserves the current issuing range in registers; SMT1 preserves the active emission cursor in its own register bank. Dispatch masks itself before arming one bulk copy, then queues its continuation or accepts the next job once the range is fully issued. The completion-start handler masks itself while its buffer is emitted and enables dispatch into the other free bank. Emission handles at most four entries per continuation. A bank becomes free only after its outgoing messages have entered the send queue.

Bulk return ID1 updates the AC remaining counter without producing a handler notification. A coalesced software checker bridges zero remaining to a local completion event. It sleeps while the previous bank is being emitted; final emission wakes it using an atomic pending flag. Short static-directory jobs use the same engine. This prevents manual ID2 loads from overlapping a change to the shared AC destination base. Reverse processing restores the scratchpad base after every forward bank and copy has drained.

Traffic uses four NoC priorities, with zero highest: range jobs3, bulk reads2, plastic spikes/static scatter commands1, and posted weight stores0. Tree control and completed-range reports also use priority0. Synapse stores have no receipt or software write credit; the send captures the value before its software slot is freed. Manual scalar reads retain their separate twelve-request credit window and handler0 completion queue. Within a timestep each physical weight is read before its update, and quiet-post forward updates are disjoint from fired-post reverse updates.

The tree payload replaces repeated global forward queries with two completion conditions. First, each worker returns one priority0 completion per delegated range after sending its last chunk. It frees the bank before sending that report, and keeps the range's emitted-delivery count in an SMT1 register. Each home contributes once to the work reduction when it has issued all jobs and received all of their completions. This produces the total expected forward delivery count; even a sentinel-only range returns a completion with count zero. These messages acknowledge completed range processing, not weight-store retirement, and do not allocate write credits.

Second, the root broadcasts one receiver-closing command. Each PU contributes one snapshot of its received-spike counter to the reduction tree. Spikes handled after the snapshot wake a coalesced service that forwards positive count increments up the same tree. The root starts reverse only after every initial contribution has arrived and initial plus late counts equal the expected deliveries. Every processed plastic range has received its bulk response, and every counted static delivery implies acceptance of its scatter request by the MC. This ordering requires no additional forward MC ping. Posted stores still need the separate timestep drain below.

Receiver arming first disables handlers 13 and 3, initializes the receiver state, installs the service on SMT0, switches the spike entry to one that requests a wake, and then enables the child-count handler. The initial snapshot runs on SMT0 after any old spike handler on that pipe finishes. One atomic pending bit coalesces wakes; the service clears it before sampling the received count. Only SMT0 updates the exported-count watermark and child increments. The root uses an atomic once flag to prevent duplicate phase transitions. Residual zero-work wakes retire during the existing reverse drain before handler 13 becomes the producer again. Global forward polling is removed; the local async-copy checker and reverse completion queries remain.

The range emitter reserves quota6/margin11, compared with quota5/margin10 in the polling payload, preserving the five-slot spare reserve. It sends at most four individual spikes or scatter commands, one final-range report, and one local checker wake per invocation. Producer closure uses a separate local-only queue from incoming range completions. Completion bookkeeping consumes without needing network space, and local wake/report queues are bounded.

After forward completion and reverse read/slot retirement, finish phase6 drains posted stores before trace increments or the next timestep. Every PU sends one P2 asynchronous read marker to every MC, in batches of at most four using the existing READ lines. Each marker follows the same route as that PU's earlier P0 stores to its destination, so strict priority prevents it from overtaking those stores. Global marker completion establishes that all stores reached their controllers. Only then does one leader per MC register the existing idle notification. All successful idle replies must arrive before step finalization. A controller-idle check by itself cannot rule out stores delayed in the network. The full target adds 8,192 marker reads and 16 idle exchanges per timestep; all this work remains inside the measured finish phase and timer. This uses no new RTL or per-weight completion protocol.

Generate ABI2 images from an existing validated image directory's canonical graph and initial state, without generating another checkpoint:

```sh
nix develop --command bash -c 'cd /root/workspace/ActiveN/sim/payloads && make sys/morrison_bulk_tree.bin'
nix develop --command bash -c 'cd /root/workspace/ActiveN && python3 -B datagen/morrison_bulk.py --reuse-graph <existing-images> --output <new-images> --dispatch-width 32 --dispatch-policy balanced --forward-completion tree --warmup 60 --timed 1000'
nix develop --command bash -c 'cd /root/workspace/ActiveN && python3 -B datagen/morrison_validate.py <new-images>'
```

Use the full target and HBM2 invocation in the main Morrison document. Benchmark defaults remain 60 warmup plus 1,000 measured timesteps; shorter diagnostics require the separately approved window. Keep the original graph/checkpoint and input images read-only, and reserve enough storage for generation workspace and final dumps.

With `SOFT_BRUNEL_DUMP` set, `SOFT_BRUNEL_PROFILE=1` retains passive PC, PU and MC profiles. `SOFT_BRUNEL_PROFILE_EVENTS=0` suppresses the large individual memory-event CSV records while retaining aggregate profiles and bulk-command/overlap counts. Sample columns remain samples. Bulk command columns count requests accepted by the PU's source router; bulk line columns sum the requested 32-byte lines. The cross-job overlap counter detects a new job's bulk request being injected while the preceding job's bank is still emitting. These observations do not change the payload's instruction stream.

Functional fixtures support `--bulk --timed 100`, runtime dispatch widths, `--dispatch-policy balanced`, `--forward-completion tree` and `--cross-mc-jobs`. The `chunks` case exercises row/chunk boundaries; `--stagger-fire` makes it active across successive steps, and `--static-burst` adds a large static delivery burst for receiver-closing tests. These controls are functional tests, not target-performance measurements. `morrison_check.py` checks complete per-step neuron snapshots and learning, plus home completion and initial/late delivery accounting for tree images. `morrison_learning_check.py` can replay learning and delivery counts from a completed run's observed spikes; it explicitly does not certify the membrane trajectory when snapshots are omitted.

With `SOFT_BRUNEL_DUMP` enabled, the ABI2 observer checks each completed timestep for posted stores in all PU send slots, all router input queues and allocated MC slots. It records `morrison-boundary.csv` and rejects a nonempty boundary or incomplete marker/idle control state. This passive check allows unrelated control and instruction-fetch traffic; it does not insert a simulator drain.
